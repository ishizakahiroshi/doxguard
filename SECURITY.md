# Security reporting

Do not put vulnerability details, reproduction steps, watchlists, credentials,
personal data, or private file paths in public issues or pull requests.

As of 2026-10-11, the owner has verified that GitHub private vulnerability
reporting is disabled for this repository. No other verified private submission
address is currently advertised. Do not assume that an unlisted address or a
public issue is a confidential channel.

If you do not already have an agreed private channel with the maintainer, you may
open a public issue containing only a request to arrange confidential contact.
Do not include the affected route, impact details, or proof of concept. Wait for
the maintainer to establish and confirm a private route before sharing details.
This coordination step is not a completed private vulnerability submission.

The owner can enable GitHub's private vulnerability reporting in the repository
security settings. Once enabled and independently checked, this document should
link the verified reporting form and state the supported versions and response
process. No response deadline or bounty is promised here.

Official setup guidance:
https://docs.github.com/en/code-security/how-tos/report-and-fix-vulnerabilities/configure-vulnerability-reporting/configure-for-a-repository

Public fixes and release notes are published through this repository's releases
and npm package. Please wait for coordinated remediation before public disclosure.
