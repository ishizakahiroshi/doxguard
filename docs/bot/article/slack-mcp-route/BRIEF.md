# 記事と画像の既定
## 本文
日本語、一人称の仕組み紹介と考え方の整理。本人の未経験の出来事や感情を創作しない。
仮題は「ChatGPTとClaudeからSlack経由でdotsに指示を出す仕組みを考えてみた」。タイトル案と構成はdotsが比較し自分で決めてよい。
主題は仕組みと考え方。読んだ人が自分の環境で同じ形を作れることを目標にする。ChatGPT側とClaude側の設定方法は、手順として番号付きで書く。
Zennは手順と仕組みを詳しく(type: tech)。:::message で注意点をまとめてよい。
Qiitaも手順と仕組みを詳しく。指示書・看板のファイル構成や、受付で確認する項目を具体的に。
noteは、なぜこの形にしたか、試して分かったこと、まだ足りないことを読みやすく。設定手順は要点に絞り、詳しくはZennかQiitaへ誘導してよい。
分量の目安は各5000字前後。水増ししない。大げさな成功宣言、広告口調、架空の会話、長いダッシュ表現を避ける。
3媒体とも冒頭に「この記事自体もdotsが執筆しています」を明記する。
合わせて事実整理・独立レビュー・公開補完が手元担当であることを開示し、最終実績に応じて担当記述を正確にする。
外部の数値や仕様(提供条件、権限、管理者承認の条件など)は出典URLを近くに置く。URLを置けないものは書かない。
Zennは有効なfrontmatter(title, emoji, type: "tech", topics 最大5, published)付き。
Qiitaは有効なfrontmatter(title,tags,private:false,updated_at,id,organization_url,slide:false)付き。タグは内容に沿う既存タグを最大5つ。
noteは貼り付け可能本文と推奨タグを別にする。noteは箇条書きに「・」を使い、URLの直後に文字を続けない。

## 記事末尾のフッター

AI生成画像の開示は、使った画像の実績に合わせて切り替える。hero(生成シーン)と、絵と文字を合成したinfographicを使う場合の文面は次のとおり。

## 画像
約5000字で5枚。hero1、全体要約infographic1、文字なし挿絵1、fig2の全役割を制作する。
3媒体で同じ図版を共有し、全5枚を適切な位置に挿入する。01から記事登場順に連番を付ける。
heroとinfographicを冒頭に置き、その後本文に挿絵と図。完成PNGをこのディレクトリ直下に置く。
1600x900を基本、スマホでも読める余白と文字サイズ、日本語の欠字・はみ出しを等倍目視する。Zennへ置く画像は1枚3MB以下にする。
hero: AIで文字も猫もないシーンを生成し、日本語タイトルと固定猫PNGを後から合成する。HTMLだけでheroを作らない。
固定猫はassetsの実素材をそのまま使い、再生成しない。右下に合成し、タイトルと競合させない。
infographic: 絵と文字の組み合わせ。絵は文字なしで生成し、日本語は編集可能な組版で合成する。heroの直下、最初のH2前。
挿絵: 文字、数字、ロゴなしで、2つの窓口(ChatGPTとClaude)から1つの会話を通して依頼が届く場面や比喩を伝える絵。
fig1: 仕組みの全体。案件番号→GitHubの固定指示書→Slackで依頼(ChatGPTまたはClaude)→dotsの受付→看板の更新→独立レビュー・手元検収、と外側の停滞監視の位置を正確に示す。
fig2: ChatGPT側とClaude側の設定の比較。それぞれの接続方法、投稿の名義と表示、確かめ方(自分宛てDM→dotsへ1通→スレッドで返信を読む)。
図に固定猫を入れない。一般的な飾り箱でなく因果・順序・担当が読める図にする。
既存契約内の画像生成を試す。追加有料APIは禁止。利用不可、生成、文字合成、素材合成、PNG化を別工程で記録する。
sourceと最終PNGのhash、生成経路、画像目視結果、altをsrcに残す。
