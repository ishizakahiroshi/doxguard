# 検証済みの事実と根拠
2026-10-04時点。手元の運用記録、GitHub上の指示書と看板、Slack上の実投稿を根拠にする。

## 登場するもの
dots: Slackから話しかけられる、GitHub連携された外部のAI開発エージェント。許可されたrepoの指示書を読み、別の実行環境で作業し、branchとPRを出し、同じ会話で報告する。Slackでは既定で持ち主にだけ答える。
手元のAI: ChatGPTとClaude Code。依頼の整理、指示書の公開、Slackでの連絡、成果の照合と検収を担当する。
SlackのDM: 持ち主とdotsの会話。案件ごとに「#番号 案件名」で始まる親メッセージを立て、その案件の話はそのスレッドで続ける。

## 仕組みの全体
1. 案件番号を振る。手元PCの採番台帳から #6、#7…と連番で取る。番号はGitHubのIssue/PR番号とは別。同じrepoと同じ案件keyなら同じ番号を返し、番号は再利用しない。2026-10-04時点で #1〜#11 まで振った(#1〜#5は台帳を作る前の番号)。
2. 指示書をGitHubに置く。対象repoの docs/bot/<案件slug>/ に README.md(指示)、REVIEW.md(独立レビューの観点)、PROGRESS.md(看板)を作り、pushしてcommitを固定する。dotsにはcommit固定の指示URLと、branch最新版の看板URLを渡す。
3. Slackで依頼する。#番号、repo、固定指示URL、看板URL、作業範囲、提出先、受付返信の要求を書いた短い文を送る。
4. 受付を確認する。同じ会話で、番号の衝突有無、読んだ指示commit、作業に必要な環境(言語、依存取得、ブラウザ、投稿経路など)を実際に試した結果を返してもらう。送信成功、受付、テスト成功は別々の証跡として扱う。
5. dotsが看板を更新する。区切りごとにPROGRESS.mdへ工程、担当、状態、証跡(commit、コマンド、CI)、次の一手を書き、同じ会話で要約を報告する。
6. 独立レビューと手元検収。実装した担当と別の担当がレビューする。手元のWindows実機、画面、本番に関わる確認は、dotsの完了報告とは別に手元で行う。merge、本番反映、releaseは依頼に含めない限り自動で進めない。
7. 外側から停滞を見る。非公開の監視用repoに、GitHubの状態(dotsのbranchが何commit進んだか、開いているPRとCI、dotラベルのIssue、直近の取り込み時刻)だけを読む読み取り専用のスクリプトを置いている。一定時間(既定60分)動きが無いrepoを「停滞」として出す。停滞の理由は外からは分からないので、出たらdotsに直接聞く。
看板(PROGRESS.md)は各対象repoに、停滞監視は非公開repoに置いている。監視用repoの名前と中身の固有名は記事に書かない。

## 運用で分かったこと(2026-10-02〜04の観察)
依頼の頭に短い識別子(#1など)を付けると、以後dotsがその名前で同じ依頼を指してくれる。会話が1本なので、識別子が無いと複数の依頼が混ざって取り違えやすい。
repo名とIssue番号で名指しすると、状況の質問に正確に答えた。
止まったときは、先に監視スクリプトでGitHub側の事実(branch、PR、CI)を見てから、dotsに状況を聞く。原因(承認待ち、環境の制限、依存が取れない、仕事が大きすぎる)は聞けば返ってくる。
依存パッケージの追加が要る仕事は、dotsの環境で取得できないことがあったので手元で行う。
大きいIssueは2時間以上PRが出なかった。30〜60分で終わる大きさに分けて出す。
非公開コードの受け渡しで権限の承認を求められることがある。持ち主が会話で「この件だけ承認します」と返すと通る。同じ拒否がまた出たら、また承認が要る。
dotsの返信は、こちらの投稿のスレッドに付く。トップレベルだけ読むと返信が無いように見える。

## ChatGPT側の設定(確認できている事実)
ChatGPTからdotsの会話へ、本人名義で投稿できている。Slack上の表示は「使用して送信されました @ChatGPT」。
手順の細部(どの画面で何を許可したか)は手元の記録に残っていない。OpenAIの公式ヘルプを確認し、URLを併記して書く。公式で確認できない手順は書かない。

## Claude Code側の設定(2026-10-04に実施・確認)
最初に試したclaude.aiのSlackコネクタは、claude.aiの設定画面では接続済みと表示されたが、Claude Codeには出てこなかった(ツール検索で0件、claude mcp listにも出ない)。ログインのやり直し、再起動、つなぎ直しでも変わらず、原因は特定できていない。この経路は使わないことにした。
代わりにSlack公式のMCPサーバーへつなぐプラグインを入れた。手順:
1. claude plugin install slack を実行。slack@anthropic-plugin-directory がuserスコープで入り、接続先は https://mcp.slack.com/mcp。
2. Claude Codeで /mcp を開き、plugin:slack:slack の認証(OAuth)をブラウザで済ませる。今回はワークスペース管理者の承認は求められなかった。環境によっては求められることがある(要出典)。
3. 新しいセッションを開く。認証前から開いていたセッションにはツールが出なかった。新しいセッションでは送信、履歴の読み取り、スレッドの読み取り、検索のツールが使えた。
4. 自分宛てDMに1通送って確かめる。11:59に「Claude Code からの送信テスト」を送り、返ったリンクと読み戻した本文が一致した。表示は「使用して送信されました @Claude」で、本人名義の投稿。
5. dotsへ1通送って確かめる。12:00にdotsとのDMへ「今の全体の状況はどうなってる？ 進めている案件ごとに教えて。」をメンションなしで送り、2分以内にスレッドへ案件別の状況が返ってきた。スレッドを読むツールで全文を読めた。
claude mcp list に「stored OAuth credential has no 'issuer' stamp」の警告が出ていたが、送信と読み取りには影響が無かった。
この記事の依頼(#11)も、このプラグインでClaude Codeから送る。

## ChatGPTとClaudeの使い分け
どちらから送っても、Slack上は持ち主本人の投稿として届き、表示だけが「@ChatGPT」「@Claude」で変わる。
同じ案件番号と同じスレッドを使えば、どちらのAIから送っても同じ案件として続けられる。
指示の本体はGitHubの固定commitに置くので、Slackの文面は短い連絡で済み、どちらのAIが書いても内容がぶれない。
