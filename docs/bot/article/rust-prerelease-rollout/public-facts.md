# 記事へ使用できる公開事実

観測日: 2026-10-03。以下はローカル実測を公開用に集約した材料で、個別リポジトリ名・監視語・私有ファイルを外部へ渡さない。外部で再現した結果とは区別する。追加の事実は公開ソースで確認する。

## 題材と実装

doxguardは、公開リポジトリへの個人情報混入をコミット前に検知するローカルCLI。APIキーを主に検知するスキャナを補完する。監視語はユーザーのマシンに置き、CIへ持ち出さない。Rust本体とnpmの薄いプラットフォーム選択ランチャーを持つ。

Rust候補は固定したソースsnapshotから作成した未公開の試用版。公開repoのbase commitだけでは、ローカル候補の全ソースを表さない。リンク名の検査用に追加した`includeLinkNames`は既定false。trueの場合もリンク先を読む・辿ることなくリンク自身の名前だけを取り込む。ルートのリンク拒否と入力数上限は維持する。ローカル未コミットの差分があるため、公開版で既に使える機能とは説明しない。

## 検証したこと

- 固定した最終候補のRustテスト103件が成功。
- 導入スクリプトの18ケースが成功。正常、検知時停止、入力欠落、既存hookの停止、dirty/staged hookの拒否、冪等性などを確認した。
- 既存スキャナを持つ30リポジトリへローカル候補を配置。
- 全30件で実際のindexを保持し、既存検査とCIを残した。
- 空indexでの追加検査と実hookの確認は通った。しかし、それだけでは実変更がコミットできることを証明できなかった。
- 実indexを変更しない仮想indexで、変更相当の内容と旧・新の検査を比較した。

## 判定差と現在状態

最終比較の集計は30件。旧検査が通る29件、新検査が通る14件、新検査が止める16件。新検査の検知は139件で、そのうち136件は旧スキャナが自身のソースを検査対象から除外していたことに関係する差だった。検知件数は一意な漏えい人数・一意な語数ではない。すべてを誤検知とも実漏えいとも断定しない。

旧検査で通るのに追加のRust検査で止まる15件は、通常作業への影響を確認するためRust追加gateを保留した。旧検査でも停止する1件は、旧検査の停止を維持するためRust有効群に含まれる。したがって現在の有効数15は「新検査が通る14」と同じ数ではない。

現在はRust追加gate15件有効、15件保留。全30件に候補は配置済みで直接scanは可能。保留群も旧検査を継続する。再起動時の常駐処理ではなく、コミット時にhookで呼ぶ仕組み。

自然なコミットの実使用観測は0件。数日の使用は未実施。doxguard候補の公開Releaseは未実施。短語境界など旧設定の移行漏れを修復したが、allowを検査成功のために自動追加していない。
