# 記事・画像・公開の受入

実装者とは独立したレビュー担当が利用できる場合は分離する。利用できない場合は自己レビューと明記し、独立レビュー済みを主張しない。ローカル担当は提出物と公開URLを別に検収する。

- 読んだ指示commit、成果物commit、レビュー対象commitを分け、修正後の新commitへ古いPASSを流用しない。
- [public-facts.md](public-facts.md)の事実と本文・画像の数字が一致する。30配置・15有効・15保留と、比較の旧clean29・新clean14・新block16を混同しない。
- 103テストと18導入ケースを同種の件数として合算しない。139検知・136差を一意な漏えい数として扱わない。
- 自然な実使用0、数日試用未実施、未公開Releaseを明記し、候補のbase commitだけで全source identityを説明しない。
- 旧検査保持、実index保持、仮想index利用、局所保留の判断が読者に伝わる。
- 私有repo・監視語・実パス・認証情報が本文、画像、元データ、ログ、PRにない。
- hero・infographic・挿絵・figが各1枚ある。形式・寸法・視認性・固定猫・パレットを確認する。生成失敗を隠して代替描画をAI生成と呼ばない。
- 図版の日本語と数値を点検し、完成infographicを目視する。本文の修正後は図版も再生成する。
- Qiita本文の全画像が公開URLで取得でき、ローカル相対参照や仮の差し込み目印が残っていない。
- 正しいQiitaアカウント、1記事の承認範囲、記事IDの保持、再試行時の重複防止を確認する。
- 投稿workflowの成功だけで完了せず、実記事URLの公開状態・本文・全画像を確認する。未確認を明示する。

`src/review.md`に重大度付き指摘、再現手順、対象SHA、検査結果、未実施項目を記録する。手元のarticle-lintはローカル担当が受入時に実行する。dots環境で同じ道具がなければ同等の検査と実行結果を示し、道具を使ったと偽らない。
