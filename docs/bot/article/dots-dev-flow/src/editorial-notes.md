# 媒体別の編集メモ

## タイトルの比較と採用

候補Aは仮題に近い「dotsに作り直し途中のDesklyの機能を任せてみた」。対象は明確だが、開発の型を持ち帰る読者には主題が伝わりにくい。

候補Bは「dotsに複数工程を任せる開発の型」。取り決め、最初の承認、レビューという主題を前に出せるためZennの主題に採用した。

候補Cは「CIが通っても重大な問題が残った」。実例の一部を強く扱いすぎ、CIや製品の失敗談が主題に見えるため採らなかった。

採用した媒体別タイトル:

- Zenn: dotsに複数工程を任せる開発の型 取り決めと1回の承認と独立レビュー
- Qiita: dotsへの開発依頼を連鎖にする 指示書とCIと独立レビューの実例
- note: dotsにDesklyの機能を任せてみた 途中は自動で進めて最後に読み直す

共通heroの主見出し案は「dotsに機能開発を任せる」、補助見出し案は「取り決め・1回の承認・別のAIのレビュー」。媒体ごとの長い題名をそのまま小さく載せず、共有画像と各本文が同じ主題を示すようにする。

## 構成の違い

Zennは、共通の取り決め、承認と停止、検証場所、独立レビュー、修正と受入の順に説明する。正本・状態・名義をコードより先に決める理由を詳しくし、次へ持ち帰る開発の型をまとめた。

Qiitaは、指示書で読み取れる項目、作業者の印と権限、PRのCIへの変更、二重送信の経路、テスト名とassertの照合を具体的に扱う。指示書項目の箇条書きは今回の型を再利用する際の整理であり、実際の非公開指示書の逐語引用ではない。

noteは、台帳を作る背景、毎回確認する方針を変更した経緯、停止で指示の前提を直した場面、全行レビュー、残る問題を受け入れた順に読む構成。GitHubのアカウント・権限の細かな条件は入れず、本文中の箇条書きは「・」に統一した。

3版とも、今回の最初の別製品AIレビューは初回取り込み後だったことを明記した。図1の取り込み前レビューは今回の学びを反映した次の型として説明している。

## noteの推奨タグ

本文・フッターに混ぜない公開時の設定用タグは、[note-tags.txt](note-tags.txt)を正本とする。

## 事実と根拠の対応

このメモ中のFACTS.md、BRIEF.md、REVIEW.mdは同じ記事ディレクトリの制作資料を指す。公開本文にはこれらのファイル名を出していない。

- 前作3媒体のURL、依頼の入口、案件番号、固定commit、PROGRESS.md、同じSlack会話: FACTS.md「前作」
- Desklyの説明と公開URL、ゾーン別インスタンス、メモリ試作と未実装範囲: FACTS.md「何を作ったか」
- 看板repo案を採らなかった経緯、検討シート、正本・採番・状態・名義・権限・承認方針の変更: FACTS.md「手順1」
- GitHub規約と個人repoの権限: FACTS.md「手順1」にある公式URLを各主張の直後へ配置。調整担当から公式出典の一致確認済みとの連絡を受けた
- 依頼4つ、設計の推奨、工程0停止、追加指示、CI 5種、テスト346→580件: FACTS.md「手順2」
- 初回取り込み後の全行レビュー、5つのサブエージェント、重大1・中12・軽約20・テストの食い違い約20、二重送信の経路、テストの弱さ: FACTS.md「手順3」
- R-01〜R-13、約3時間、718件、報告を問い合わせたこと、3つのサブエージェントによる再読、重大0・新しい中2、手元による取り込み: FACTS.md「手順4」
- 取り決め、停止条件、CI、別製品AIによる取り込み前の全行レビュー、assertの照合、未決事項: FACTS.md「学び」
- 著者欄、問い合わせ欄、前作リンクの回数、AI執筆と手元担当の開示、媒体書式、画像構成: BRIEF.mdおよびREVIEW.md
- AI画像の使用と編集可能な文字・図版の開示: 調整担当から共有された今回の制作方法。最終的な画像の実績との一致は画像担当・調整担当が最終確認する

新たな時刻、PR番号、commit SHA、私的なrepo名・社名・ホスト名、架空のテスト名、本人の感情や会話は追加していない。引用した方針変更の発言はFACTS.mdの記載をそのまま使っている。

## 形式検査

検査結果の詳細はeditorial-checks.json。

- ZennとQiitaはYAMLとして読み込み成功。必須項目と公開状態、最大5タグを確認
- noteはH1タイトル1つ、見出しはH2/H3、画像は指定の5行目印が5組
- 各媒体の前作URLは冒頭と締めの2か所
- 5枚の画像は01、02、03、04、05の登場順
- heroとinfographicは最初のH2より前
- Zennは/images/参照、Qiitaは相対参照
- noteのURLは単独行に置き、URL直後に文字を続けていない
- ZennとQiitaのフッターは完全一致
- noteの推奨タグは本文外のnote-tags.txtに分離
- 本文の事実はFACTS.mdと照合済み。今回の事実と次の開発に使う型は区別した

最終原稿の分量は、frontmatter・URL・画像指定・空白・フッターを除く集計でzenn 3,908字、qiita 3,978字、note 4,252字。Markdown原稿全体はzenn 5,697字、qiita 5,744字、note 7,232字。noteの増分は主に5行目印の区切り線である。約5,000字を目安にしつつ、水増しは行わなかった。

画像そのものの存在・ピクセル・容量・文字の表示は、この担当の検査範囲に含めていない。本文の挿入位置・ファイル名・altおよびnoteの内容説明を検査した。
