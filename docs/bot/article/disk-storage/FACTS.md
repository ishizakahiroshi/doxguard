# 測定済み事実と書いてはいけない主張

情報源は依頼者の実施記録。privateな元資料は公開しない。以下の数値は今回の実測で、一般的な効果の保証ではない。

- 最初の開発ドライブ空き3.26 GiB。既存の清掃道具でRust target5か所、Goビルド/依存キャッシュ、pnpm未参照パッケージを整理し、25.97 GiBへ。約22.71 GiB増。
- 次の部分移設と整理を終えた時点の空き27.15 GiB。今回さらに約1.18 GiB、最初から約23.89 GiB増。GiBで統一し、単純なGB換算や論理サイズとの混同を避ける。
- 用途を確認した完成動画17本、合計37,911,314 bytesを外部の保管先へコピー。全件の元/コピー先/復元コピーでSHA256一致、外部から全編ffmpegデコード成功。先行1本を画像で目視。確認後に元と復元用コピーを整理し、外部17本を保持。ソース・ログ・フォントは保持。
- 未使用Rust target1か所を公式cargo cleanで整理。ソースと未追跡変更は保持。他の現役データを一括削除しない。
- 外部保管先はリモートデスクトップ経由で見える通常ディレクトリ。開始時の利用可能容量は約217.48 GiB。存在だけでなく書込み、読み戻し、完成物の利用、復元を確認した。実ホスト名と実UNCパスは書かない。
- 1件の必要なRust CLI復元で、外部への直接cargo buildはtemp-archive削除時のWindows error87で失敗した。正確な原因は確定していない。すべてのネットワーク先でCargoが使えないという結論にはしない。
- 同じソースをDの作業専用一時targetでビルドすると15.38秒で成功。完成exe6,815,232 bytesを外部へ保管し、Dにも利用用の小さなコピーを保持。SHA256一致、両方でversion成功。隔離した合成Git fixtureの検出ケースと許可ケースも期待する終了値・件数に一致。
- 合成検査の今回の所要はDが0.122/0.107秒、外部が2.092/2.128秒。単発測定なので一般的な速度比を断定しない。本文では必要なら約0.1秒と約2秒と説明する。
- ビルド中間物はローカル・外部とも公式cargo cleanで片付け、対象の消滅を確認。Dには約6.5 MiBの完成exeを保持。
- 約20.55 GiBのローカルデータには公開候補と受入証跡が多く、用途未確定の出力もあったので保持。同期フォルダ、アプリ本体、既存hook、採用済み候補も変更しない。
- 配置台帳と手動Inspect/Clean道具を用意。finishedの専用Cargo targetをID指定し、dry-runからApplyへ進む。sourceとtargetの重なり、共有ディレクトリ、リンク、稼働プロセス、所有マーカー不一致を拒否する。保管artifactの削除機能と無条件の定期削除はない。
- 親の独立レビューで共有フォルダを誤登録した時の清掃範囲の穴を発見し、修正した。子の成功報告だけで合格にしない。
- 今後の方式はDで作業単位のビルド、必要な完成物だけ外部保管、動作確認後に中間物を清掃。ソースと普段の実行用小さなexeはDに保持。
- 接続切断/再接続試験と普段の全アプリ起動試験は未実施。定期チェック、通知、全AIの共通ルールへの組込みは未設定。見直し日は人が確認する目安で自動削除期限ではない。完全自動・放置で容量維持と書かない。
