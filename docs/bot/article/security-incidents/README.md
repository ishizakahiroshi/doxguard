# #20261006-001 国内インシデント一次情報の記事の書き換え（note）

Agent: dot

## 目的と範囲

依頼者が書いた note 向けの原稿 SOURCE.md を、依頼者の文体ルール（BRIEF.md）で書き換える。新しく調べて書く記事ではなく、**書き換え**が主題。題材は、2026-09-29 から 10-05 ごろに企業・組織が公表した国内のセキュリティインシデントを、各社の一次情報へ戻って並べ、「全部ハッシュ化すればいいのか」という問いへつなげる論考。

書き換えで変えるのは文体・構成の見せ方・画像・体裁だけ。事実、数値、日付、各社の発表内容、依頼者自身の感想と論点は SOURCE.md から落とさず、足さない。原稿に無い体験談や数字を創作しない。事実の根拠と確認状況は FACTS.md、書き方と画像の条件は BRIEF.md、レビュー観点は REVIEW.md。

担当 dots は、本文の書き換え、各社の一次情報の再確認と SOURCES.md の作成、brief 指定の全画像（hero・infographic・本文挿絵・fig）の制作と自己検査、独立担当によるレビュー、専用 branch の Draft PR 提出を行う。手元担当は提出後に全差分と全画像を検収し、hero へ固定猫を重ねる。

このリポジトリは記事制作の受け渡し先で、製品の宣伝記事ではない。製品ソース・設定・他の記事は変更しない。

変更許可は docs/bot/article/security-incidents/ 配下だけ。素材・HTML・生成プロンプト・検査証跡は src/ へ。成果物は draft.md、x-post.md、SOURCES.md、完成 PNG。私有情報、手元のパス、認証情報は取得しない。

## 提出と承認境界

この指示 commit から dots/article-security-incidents-20261006-001 のような専用 branch を作り、main 向けの Draft PR を提出する。範囲内の調査、制作、修正、commit/push、PR 提出は進めてよい。merge、note への投稿、サイト掲載、SNS 送信、release、課金、認証設定は行わない。制作の依頼は公開操作の承認とは別。

まずこの番号の衝突有無、読んだ指示 commit、Web 閲覧（各社の公式ページを開けるか）、本文、画像生成、文字合成、PNG 描画、ブラウザ目視の実行可否を同じ案件会話へ返す。未確認の能力を不能と決めず、必要な工程を実際に試す。固定猫の素材は不要。

各社の公式ページを開けない場合は、開けなかった URL と理由を記録し、SOURCE.md に書かれた内容を「原稿記載のまま・dots では未確認」として扱う。確認できなかった事実を、確認できたかのように書かない。

本文と独立した素材制作は並列でよい。数値に依存する図版の確定、Git 書込、看板統合は一担当が直列所有する。工程の開始・停止・提出時に PROGRESS.md を更新し、同じ会話へ要約と最新看板 URL を返す。

提出時は PR URL、head SHA、独立 review 対象 SHA、検査結果、PNG の実寸法と枚数、本文字数、画像役割、採用生成元、確認できた一次情報と確認できなかった事項、未完了と次の入口を示す。依存取得や生成ができない場合は、安全なエラー分類と試した代替手段を残し、制作済みの成果を保持する。私有の絶対パスを生ログのまま転記しない。
