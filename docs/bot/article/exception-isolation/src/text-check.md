# 本文と告知文の検査記録

## 対象と結果

- 対象: `draft.md`、`x-post.md`。
- 題材の事実は、同じ依頼ディレクトリ内の `FACTS.md` のみを使用。`README.md`、`BRIEF.md`、`REVIEW.md` は制作条件として参照。
- 本文: 3,932字。frontmatterとフッターを除き、画像記法、リンクURL、見出し記号、強調記号、コード装飾、空白を除外。見出しとリンク表示名は含む。箇条書きの先頭記号は含む。
- 同範囲のMarkdown原文: 4,332字。約4000字に対して図版は4枚。画像参照はhero、infographic、fig、illustration各1回。
- 告知文: 128字。先頭行で読者の利益を示し、URLは指定の差し込み用文字列。想定アカウントは制作条件どおり。送信なし。

## 事実の対応

- 導入と「まずは変えてはいけない振る舞いを並べる」: 捕捉経路の調査と記録追加、および戻り値・再送出・応答・トランザクション・再試行・後片付けの確認。
- 「捕捉した場所では保留し、別の処理で台帳へ反映する」: 保留保存、別の回収処理、専用トランザクション、反映確定後の保留データ除去。保留と確定の区別。
- 「自動報告でセッションの動きを変えない」: 認証セッション・最終操作時刻への副作用の回避、保存前のセッションロック解放。
- 「保存する項目は許可リストで決める」: 分類・発生箇所・関連づけ用識別情報に限定。生メッセージ・SQL・入力本文・Cookie・引数は保存しない。
- 「通常の失敗まで不具合にしない」: 入力不備・権限拒否・競合・取消の分類、記録対象と除外理由、例外を投げない失敗と未完了の検討。
- 「テストで確かめたことを分けて書く」: 静的検査、合成データ・代替依存による失敗注入、CI、配信ファイル一致、現行仕様への反映。実操作から台帳までの通し確認、ブラウザ確認、スモークテスト、実データ投入は未実施と明示。
- 「記録できない境界まで含めて設計する」: 重複抑制、容量・回収量の上限、保持・停止方法。容量超過・回収停止・認証期限切れ・強制終了、exactly-onceや影響ゼロを保証しないこと、ログアウト時の消去を断定しないこと。
- 具体的な見直し方は上記事実の設計上の説明として記載。未提供の実装手順、検査件数、性能値、固有構成、外部技術仕様は追加していない。コード例なし。
