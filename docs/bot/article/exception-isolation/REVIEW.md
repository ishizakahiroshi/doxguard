# 独立検収

- FACTS.mdの事実だけを用い、未確認の実操作を成功へ置換していない。
- 保留保存、台帳確定、配信一致、静的検査、合成検査、実画面確認を区別している。
- 記録失敗を抑える設計と、業務失敗を隠すことを混同していない。
- 通常の入力不備・取消まで無条件に起票する設計を勧めていない。
- 必ず記録、影響ゼロ、完全な重複排除、常にログアウトで消去と断定していない。
- 会社・案件・人物・元のコード名・実日付・実件数・環境構成が本文、frontmatter、画像、生成指示、元データ、告知文、PR本文、進捗記録にない。
- 秘密に見えるランダム値や実値の部分マスクがない。値が必要なら明らかな説明用のplaceholderだけを用いている。
- 図は概念図であり、元の構成や実画面の再現ではない。heroの固定猫領域が空いている。
- 完成画像を目視し、本文との一致、日本語、切れ、ロゴ混入を確認した担当と結果が残っている。
- 画像の枚数、実PNG、本文への差込み、AI生成の開示が整合している。src/と完成物が分離されている。
- 擬似コードを実装済み・実行済みと主張していない。外部仕様の追加は公式資料で裏づけた。
- リンク先は実在して対象の説明を支持する。非公開資料やdraftリンクを入れていない。
- 長いダッシュ記号を使っていない。Qiitaタグに加えて本文末尾のハッシュタグ行を置いていない。
- 投稿・公開・送信・merge・別repo反映が行われていない。

独立レビューの対象commitと指摘・修正結果をsrc/review-result.mdへ記録する。dots内のレビュー完了後も、手元による別の検収は必要。
