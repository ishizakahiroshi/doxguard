# 既定で確定した制作条件

1. 媒体: note。
2. hero: Web画像生成を試す。追加課金なし。猫なしの1600x900 PNG。
3. infographic: 1枚。絵は文字なしで生成、文字はHTMLで合成。絵の取得に失敗した場合はHTML組版に切り替え、理由を記録。
4. 色: 温かめ。カリブの海のティール、砂のベージュ、白、アクセントにコーラル。4枚を統一。
5. 分量: 論考として約4,500字。
6. 完成画像: 計4枚。hero、全体要約infographic、本文挿絵1枚、数値を正確に示すfig1枚。
7. 記事タイプ: 論考（社会・制度）に本人の感想を添える。ニュースの要約で終わらせず、ドメインという足元から見た構造を書く。
8. 題材: FACTS.mdの起点と、dotsが確認した一次情報。
9. 検索語: SI、Super Intelligence、.aiドメイン、アンギラ、.siドメイン、スロベニア。導入の200字以内に自然に入れる。
10. 冒頭の別TL;DR: なし。infographicで要約する。
11. 機密: 個人。私有情報なし。
12. タイトル: 1案を選んで提出。方向の例は「AIがSIに呼び変わる日、.aiで予算の半分を稼ぐ島はどうなるのか」。煽りを避け、確認できた数字だけを使う。
13. 題材分類: misc。指示書を置くrepoと記事の主題を混同せず、製品の宣伝ブロックは不要。
14. タグ: note用ハッシュタグ13個（基本10＋旬3）を、フッターの後ろ・記事の最終1行に `#` 付き半角スペース区切りの1行で置く。
15. 今回の公開範囲: 制作とDraft PR提出まで。note・サイト・SNSへの投稿は行わない。
16. 音声: なし。
17. 制作担当: dots。固定猫を重ねる工程と最終独立検収だけ手元。

## 文体と構成

敬体、短い段落（1段落1〜3文）。上から教えず、調べた順に分かったことを書く。一人称は控えめ。禁止ダッシュ（em dash、全角ダッシュ、その連結）を本文・見出し・図のすべてで使わない。H2は会話的・問題提起型にする（例「予算の半分が、2文字のドメインから来ている」）。体言止めの多用、「重要なのは」「〜と言えるでしょう」型の総括、三段構成のテンプレ感を避ける。文の長さを不揃いにし、短い言い切りを時々挟む。

流れの目安: 大統領令とSpaceXSIのニュースを見た場面（「たけえ」）から入る。→ 何が決まったのか（原典で確認した範囲）。→ .siに何が起きたか（登録急増、運営側の慎重な見方、先回り取得となりすましの懸念、spacexsi.comの例）。→ .aiのアンギラはどれだけ依存しているか（年ごとの数値、ブーム前との比較）。→ 呼び名が変わると.aiはどうなるのか（分かっていることと分からないこと、島が取りうる道として一次情報や報道に出ている選択肢）。→ 本人の感想（箱物行政の匂い、AIでええやん）。大きな教訓で締めず、小さく静かに終える。

本人の感想は注釈として扱う。本文の事実の流れを止めずに、※の一文または短い補足段落で「個人的には」と明示する。

## 出典の付け方（最重要）

論文・記事・X投稿・公式資料に言及したら、その段落末か直後の1行にURLを置く。「報じられています」だけで終わらせない。一次情報（政府・レジストリ・IMF等）と報道を区別し、本文では一次情報を優先して引く。noteではURLの直後に説明やカッコを続けない（リンクが壊れる）。説明はURLの前の行か前に置き、URLで行を終える。

SOURCES.mdに、本文で使った全出典を「主張 / URL / 一次か二次か / 確認日 / 確認できた範囲」で一覧にする。使わなかったが調べた資料と、見つからなかった一次情報も分けて残す。

## 画像と差込み

完成PNGは01_hero.png、02_infographic.png、03_illustration.png、04_fig.png。1600x900を基本とし、素材とHTML/SVGはsrc/へ。heroは猫を描かず重ねず、1600x900の右下 幅340×高さ250pxを空け、タイトルと被らせない。猫は手元が重ねる。固定猫素材は要求しない。

heroは、カリブの小さな島の看板やブイに書かれた「.ai」の文字が、向こうから来る「.si」の波を見ているような情景と短い日本語タイトル。実在のロゴや実在人物の顔は描かない。infographicは「大統領令 → .siの登録急増と先回り取得 → .aiに頼る島の収入」の3列の要約。挿絵は、ドメイン販売ページの高い値札を前に固まる人の場面（人物は特定できない描き方）。figは.aiの年別収入と予算比、または.siの月別新規登録の比較など、一次情報で確認できた数値だけで作る正確なグラフ。本文の数値と同期させる。

draft.mdはnote形式。H1がタイトル、本文の章見出しは`## `、小見出しは`### `、箇条書きは`・`。画像位置は単独1行ではなく、長い`=`区切り線を前後2本ずつ置く5行の目印ブロックにする。

```text
===========================================================================================
===========================================================================================
【画像N｜<画像の内容>｜<ファイル名.png>｜ここに差し込み、この行は削除】
===========================================================================================
===========================================================================================
```

AI生成の挿絵は`【挿絵N｜…】`とする。heroは冒頭、infographicは導入の後かつ最初のH2の前。挿絵とfigは対応する節に置き、目印ブロックの直後に画像がなくても意味が通る説明を1〜2文添える。

AI画像生成、文字合成、PNG化、目視を別工程として記録する。可能ならWeb生成を並列にし、最初に採用した生成元で記事内の絵を統一。未試行で画像制作不能としない。日本語の文字化け、切れ、画像抜け、絵への文字・ロゴ混入、余白、1600x900、横溢れ、目印ブロックのファイル名と実ファイルの一致を確認する。
